# 2026-10-27 手机首页与歌曲分享优化

对照版本为已发布的 `ab6b4cd`，在修改前保存完整生产构建快照；候选版本由同一个构建命令生成。账号、认证请求、数据库、CSP 和安全配置未修改。

## 改动范围

- 手机首页正文、标题、歌曲名和中文导航使用本机字体，只预加载 8,772 字节的 Station Mono。原有脚本已经使用 `defer`；保留依赖顺序，语言初始化只更新发生变化的文字。
- 初始歌曲为 6 首代表作，保留全部歌曲档案入口及“搜索／收藏全部歌曲”按钮。带搜索、排序或收藏条件的链接仍显示完整筛选结果；展开后清空搜索不会隐藏输入框；键盘 `/` 先展开再定位搜索框。
- 手机 X 动态显示 2 条；切换创作者及语言、改变窗口宽度后计数保持一致。关于、来源说明、留言表单及页脚补充说明可展开，桌面全部展开。无 JavaScript 时内容仍在 HTML 中，可通过原生折叠控件和档案链接阅读。
- 手机画廊初始 6 幅，展开后构建全部 107 幅；保留大图前后浏览、键盘方向、浏览器后退及焦点恢复。手机用 220px 缩略图，桌面 300px 图与大图逐字节保持不变。
- `songs.html` 手机歌名 18px，导航和歌曲链接最小触控高度 48px；规则仅限歌曲列表手机版。
- 52 首歌曲页使用各自官方 `i.ytimg.com/vi/<ID>/hqdefault.jpg` 作为 Open Graph / Twitter 封面。52 个地址均验证为 HTTP 200、JPEG、480×360；元数据在初始 HTML 中，不依赖脚本。

## Lighthouse 对照

使用 [Lighthouse 官方 CLI](https://github.com/GoogleChrome/lighthouse/blob/main/docs/headless-chrome.md)，版本 13.5.0、Chrome 156；同机临时 HTTP 服务器分别提供旧快照与新生产构建。手机使用默认模拟设备（412×823、模拟节流），桌面使用 `--preset=desktop`。每次使用工具的临时浏览器环境，没有用户账户资料。测试没有向留言接口写入数据。

桌面单次性能 96 → 98，页面高度均为 7,237px；以上手机和桌面自动无障碍与 SEO 均为 100。不同机器、网络、缓存和内容会导致分数变化，这些结果不能与其他环境的 48 分直接对比，也不是所有访客的速度保证。页面仍略长于原先估计的 4–5 屏；保持留言、来源与完整内容可达。

歌曲列表在 375px 宽度的同配置对照均为性能 87、无障碍 100、SEO 100；新版 320px 也为 87／100／100。检查两种宽度的 Lighthouse 截图，页头、导航与歌曲条目没有横向裁切。这里没有把分数变化归因于字号，也没有将截图检查当作真实点击验收。

画廊资源体积比较：全部手机缩略图 659,586 字节，旧缩略图 1,028,446 字节（减少 35.9%）；初始 6 张资源 22,516 字节，旧版首批 15 张 97,168 字节（减少 76.8%）。这是文件大小对照，不是每个访客实际下载量。

## 验证边界

行为测试覆盖手机歌曲筛选、展开、搜索快捷键、收藏、语言切换、跨屏宽恢复，以及画廊展开／收起、大图后退和焦点。浏览器交互工具被 Work 设置禁用，因此没有将事件测试描述成真实点击或真机 Safari 验证。Lighthouse 提供加载诊断与自动无障碍检查，不能替代完整人工交互验收。

社交平台的缓存和客户端行为由平台决定；本次验证分享元数据及图片可获取，没有实际向 X 或微信发布测试分享。

完整本地诊断报告保存在被 Git 忽略的 `artifacts/performance-20261027/`。上线结果以对应提交的 Verify / Publish 工作流和线上资源核对为准，不能把本地测量等同已经发布。
